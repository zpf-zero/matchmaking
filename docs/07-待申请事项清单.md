# 待申请事项总清单

> 最后更新：2026-10-21  
> 用途：**一次讲清所有需要对外申请、审批、购买、配置的事项**，以及每项在开发阶段的降级方案。
>
> 核心原则：**开发阶段优先保证功能实现**。凡是有降级路径的，一律先做 Mock/本地实现，把功能跑通；  
> 只有真正卡住上线的才标 🔴 红色。

## 结论速览

| 级别            | 含义                        | 项数  |
| ------------- | ------------------------- | --- |
| 🔴 **阻塞上线**   | 不办就无法提审 / 无法上线，**必须最早启动** | 3 项 |
| 🟡 **阻塞真实能力** | 不办能用，但走的是降级实现，上线前须切换      | 5 项 |
| 🟢 **上线前完善**  | 不阻塞功能，属合规与体验收尾            | 4 项 |
| ⏭️ **一期明确不做** | 已决策取舍，非缺陷                 | 4 项 |

**最关键的一句话**：技术全部可控，**唯一由外部决定、且周期最长的是资质审批**（见第 1 项）。  
其它所有事项都可以在开发阶段用降级方案先行，不影响你验收功能。

**替代路径（强烈建议先走这条）**：  
向通信管理局提交申请，**拿到《不予受理通知书》**（而不是许可证），把该通知书提交微信后台。  
微信对此有明确的二次审核通道，可过类目审核。**这条路周期短得多，应当今天就去问。**

> ⚠️ 这是全项目**唯一不能靠技术解决**的事。建议立刻联系当地代办或自行向省通信管理局咨询。

## 二、🟡 阻塞真实能力（5 项，上线前须切换）

这些**都有降级实现，开发阶段完全不卡**。上线前按表中「切换动作」改配置即可，**业务代码零改动**。

### 4. 小程序 AppID + AppSecret

| 项        | 内容                                                                                                                                      |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| **要什么**  | AppID + AppSecret（小程序后台「开发管理 → 开发设置」）                                                                                                   |
| **代码位置** | `server/config.dev.yaml` / `config.prod.yaml` 的 `wechat.app_id` / `app_secret` / `mock`；`miniapp/src/manifest.json` 的 `mp-weixin.appid` |
| **当前降级** | `wechat.mock: true` —— 登录把前端传的 code 当 openid 落库；手机号前端手填；文本安全走本地敏感词库                                                                     |
| **切换动作** | 三个 YAML 字段填上 + `mock: false` + 填 manifest appid，**重启服务即可，业务代码不动**                                                                       |

**为什么能零改动切换**：`server/internal/pkg/wechat/wechat.go` 把 `Code2Session` / `GetPhoneNumber` / `MsgSecCheck`  
抽象成 `Client` 接口，`mockClient` 与 `realClient` 是两个实现，由 YAML 开关选择。上层 service 只依赖接口。

> **注意**：切换真实模式后，**mock 模式建的历史账号 openid 是假的**，真实登录会是全新账号。  
> 上线前需清理测试数据或接受数据断层。

### 5. 手机号快速验证组件

| 项        | 内容                                                                                                                                     |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------- |

### 6. 隐私保护指引（用户隐私协议配置）

| 项        | 内容                                                                                                                                                         |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **要什么**  | 小程序后台「设置 → 服务内容声明 → 用户隐私保护指引」，声明收集的信息类型                                                                                                                    |
| **需要声明** | 手机号（用于账号与联系）、相册/摄像头（用于上传头像与相册）、昵称头像（用于展示）、**所属行业**、**原生家庭信息（父母职业类型、家庭氛围、是否独生子女、家庭所在地、补充说明）**、**三观问答答案**                                                    |
| **代码位置** | `miniapp/src/pages/common/agreement.vue`（应用内协议）+ 微信后台配置（**尚未配**）                                                                                           |
| **前端兜底** | ✅ 已接入：`App.vue` 的 `setupPrivacyGuard()` 用官方 `onNeedPrivacyAuthorization` + `requirePrivacyAuthorize` 弹一次官方授权框，用户同意后全小程序隐私接口解锁。**但这只是用户侧交互，后台未声明时即使同意也调不通** |
| **阻塞范围** | 未配置时，`getPhoneNumber` / `chooseAvatar` 等接口**会直接调用失败**（`errno:104` / `api scope is not declared in the privacy agreement`）                                  |

> 这是**最容易被忽略但一定会卡住的一环**：接口在开发者工具里可能正常，真机上线后立刻报错。

> ⚠️ **v1.3 权益重构后必须同步更新本项**：原生家庭与三观问答都是新增的个人信息收集项，且原生家庭属敏感信息。微信后台声明的收集范围、应用内隐私政策（`agreement.vue` 第二节「信息收集范围」/「信息展示」已同步更新）两处**必须与实际收集字段一致**，否则会以「隐私政策与实际不符」被驳回。原生家庭要特别说明「默认不对外展示、需用户主动授权」。

### 7. 微信内容安全（`msgSecCheck` / 图片安全）

| 项        | 内容                                                                |
| -------- | ----------------------------------------------------------------- |
| **要什么**  | `msgSecCheck` 随 AppID 即可用，无需单独申请                                  |
| **代码位置** | `server/internal/pkg/wechat/wechat.go` 的 `realClient.MsgSecCheck` |
| **当前降级** | 走 `server/configs/sensitive_words.txt` 本地词库 + 联系方式正则              |
| **未接入项** | **图片内容安全**（当前头像/相册走人工审核，聊天图片靠举报处理）                                |
| **切换动作** | 关闭 mock 后文本自动走微信接口；图片安全需另行接入，属凭证到位后的补充项                           |

> **设计要点**：微信接口异常时**放行但记日志**（`wechat.go:145/164/168`）——  
> 不能因为第三方抖动就让用户发不出消息。本地词库始终是第一道闸。

### 7.1 短信验证码通道（H5 手机号登录新增）

| 项        | 内容 |
| -------- | --- |
| **要什么**  | 阿里云短信**签名** + **模板**（模板变量名必须是 `code`，如 `{"code":"123456"}`），在阿里云控制台申请 |
| **代码位置** | `server/config.dev.yaml` / `config.prod.yaml` 的 `sms.*`；`server/internal/pkg/sms/sms.go`（Mock 与阿里云 Dysmsapi 两种实现）；接口见 `docs/03` 认证章节 |
| **当前降级** | `sms.mock: true` —— 验证码不真实下发。开发环境由 `/auth/sms/send` 回传 `dev_code` 并写日志；**生产（`server.mode=release`）绝不回传**，所以未配置通道前 H5 登录不可用（不是安全漏洞，是功能未开通） |
| **切换动作** | 填 `access_key_id / access_key_secret / sign_name / template_code` + `mock: false` + 重启。业务代码不动 |
| **阻塞范围** | 只阻塞 H5 手机号登录；小程序微信登录不受影响 |

> 限频与安全：同手机号 60 秒冷却、24 小时 5 条；同 IP 每小时 20 条；验证码 6 位、5 分钟、最多错 5 次、用后即焚；库里只存 HMAC 哈希。
