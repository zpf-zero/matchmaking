## 一、发布链路总览

```
本地开发 ──预览──→ 真机调试（无需任何资质）
    │
    └──上传──→ 开发版本 ──选为体验版──→ 团队内部试用
                    │
                    └──提交审核──→ 审核通过 ──发布──→ 全网用户
```

**核心认知：预览/开发版 与 提审版 是两个世界。**

| | 预览 / 体验版 | 提审 / 正式版 |
|---|---|---|
| 域名要求 | 不校验（`urlCheck: false` 已配好），HTTP + IP 可用 | **必须 HTTPS + 已备案域名** |
| 类目资质 | 不查 | 「社交-婚恋交友」类目必查（ICP 经营许可证或《不予受理通知书》） |
| 隐私指引 | 建议先配好（真机授权组件需要） | **强制** |
| 当前状态 | ✅ 技术上已就绪 | ❌ 被域名/资质卡住 |

## 二、前置准备（一次性）

### 1. 部署后端到服务器

小程序的 API 请求要打到后端，后端必须先在线上跑着（真机访问不到你电脑的 localhost）：

```bash
scp deploy/matchmaking-ubuntu-amd64.zip ubuntu@81.70.160.36:/tmp/
ssh ubuntu@81.70.160.36
cd /data/matchmaking && sudo unzip -o /tmp/matchmaking-ubuntu-amd64.zip && sudo bash deploy.sh
# 验证：curl http://81.70.160.36/health
```

包是现成的（2026-10-25 构建，含真实微信模式）。之后改了后端代码需要重新跑 `deploy/build.ps1` 打包。

### 2. 确认扫码人有权限

微信开发者工具扫码登录用的微信号，必须是该小程序的**开发者**或**管理员**：

- 登录 [mp.weixin.qq.com](https://mp.weixin.qq.com)（用小程序管理员微信扫码）
- **管理 → 成员管理 → 项目成员**：把自己的微信号加为开发者（管理员默认有权限）

### 3. 微信后台配置隐私保护指引（真机授权前置）

**设置 → 服务内容声明 → 用户隐私保护指引**，声明使用的敏感信息（对照代码实际用到的）：

| 接口 | 声明项 | 用途描述 |
|---|---|---|
| `chooseAvatar` | 头像 | 用户设置个人头像 |
| `type="nickname"` | 昵称 | 用户设置昵称 |
| `getPhoneNumber` | 手机号 | 账号绑定与登录凭证 |

**不配的话，真机上点「一键授权头像/手机号」会直接报错**（开发者工具里可能看不出问题）。这是 docs/07 第 6 项，目前**未配置**。

## 三、真机预览（现在就能做）

1. 打开微信开发者工具（本机路径 `D:\software\微信web开发者工具\微信开发者工具.exe`）
2. **导入项目**：
   - 项目目录：`D:\work_home\person_grow\matchmaking\miniapp\dist\build\mp-weixin`
   - AppID 自动读取（产物内 `project.config.json` 已带），不用手填
3. 工具右上角**扫码登录**（用有开发者权限的微信）
4. 确认「详情 → 本地设置 → 不校验合法域名」已勾选（产物默认已配）
5. 点工具栏**预览** → 生成二维码 → 手机微信扫码

手机上跑起来的就是**真实模式**的小程序：

- `wx.login` 走真实 `jscode2session`（每个微信号对应一个账号）
- 「一键授权头像/昵称/手机号」走官方组件（前提：隐私指引已配好）
- 文本内容安全走真实 `msg_sec_check`
- 所有请求打到 `http://81.70.160.36`

### 预览时建议验证的清单

- [ ] 微信登录后进入资料向导
- [ ] 授权头像 + 昵称（chooseAvatar / type="nickname"）
- [ ] 一键授权手机号（getPhoneNumber，**需隐私指引先配好**）
- [ ] 完善资料 → 提交审核 → 管理端（用超管账号）审核通过
- [ ] 推荐流、筛选、喜欢、配对聊天
- [ ] 邀请页分享卡片 → 对方点开落地

### 常见问题

| 现象 | 原因与处理 |
|---|---|
| 扫码提示无权限 | 扫码微信号不是项目成员，去 mp 后台加开发者 |
| 真机请求全部失败 | 后端没部署或挂了，先 `curl http://81.70.160.36/health` |
| 点授权报错 `fail api scope` / 无弹窗 | **隐私保护指引没配**，见第二节第 3 步 |
| 手机号授权报 41008/43101 | 隐私指引中未声明「手机号」；或主体非企业（个人主体无此组件权限） |
| 开发者工具正常、真机异常 | 大概率是域名/HTTPS 差异——真机对网络环境更严格 |

## 四、上传体验版 / 提审

功能验证通过后：

1. 工具栏点**上传** → 填版本号 `1.0.0` + 备注（如「首版」）
2. mp.weixin.qq.com → **管理 → 版本管理 → 开发版本**
3. 「选为体验版」→ 二维码发给团队成员，体验版有效期 90 天
4. 准备提审时点「提交审核」——**但先看第五节的门槛**

提审时微信会要求填写：

- **类目**：社交 → 婚恋交友（需要资质，见下）
- **隐私协议**：用户隐私保护指引（与第二节第 3 步是同一份）
- **账号检测**：小程序内不能有测试账号/测试数据（上线前清理测试用户）

## 五、上线前必须补齐的硬门槛

按阻塞程度排序（**周期倒排，最早启动**）：

| # | 事项 | 周期 | 说明 |
|---|---|---|---|
| 1 | **ICP 经营许可证**（婚恋类目资质） | 法定 60 工作日，实际 3~6 个月 | 全项目最长链路。**替代路径**：向省通信管理局申请拿《不予受理通知书》提交微信后台，可过二次审核，周期短得多。前置条件：企业主体 + 已备案域名 |
| 2 | **域名 + ICP 备案 + HTTPS 证书** | 15~20 工作日 | 备案是许可证的前置。证书到位后一条命令切换：`deploy\build.ps1 -BaseUrl https://你的域名`（同时改前端 base_url、上传域名与 nginx server_name），证书放 `/data/matchmaking/nginx/ssl/`，再重新打包部署 + 重建小程序 |
| 3 | **企业主体 + 微信认证**（300 元/年） | 1~3 工作日 | 当前 AppID 所属主体类型待确认（mp 后台「设置 → 基本设置」可查）。个人主体**不能**开婚恋类目 |
| 4 | 隐私保护指引 | 即时 | 见第二节第 3 步 |
| 5 | 生产配置收尾 | 即时 | `jwt.secret` ✅ 已换（2026-10-26，dev/prod 不同值）；短信通道（如 H5 要用）申请签名后填 `sms.*` 并关 mock |
| 6 | 测试数据清理 | 上线前 | 清理 test_user_* 等测试账号，避免审核时被检测到 |

## 六、日常迭代流程（上线后）

```bash
# 1. 改代码（miniapp/src 或 server）

# 2. 小程序重新构建
cd miniapp && npm run build:mp-weixin
#    ⚠️ 构建完 src/config.generated.ts 是 prod 地址，本地开发记得 npm run config:dev 还原

# 3. 后端有改动则重新打包部署
powershell -ExecutionPolicy Bypass -File deploy\build.ps1
scp deploy/matchmaking-ubuntu-amd64.zip ubuntu@81.70.160.36:/tmp/
# （服务器上解压 + bash deploy.sh）

# 4. 开发者工具导入 dist/build/mp-weixin → 预览验证 → 上传 → mp 后台提审
```

注意：`deploy/build.ps1` 只构建 H5，**不构建小程序**——两个产物去向不同，小程序必须单独跑 `build:mp-weixin`。
